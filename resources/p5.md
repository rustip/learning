
## Unit 1: SQL

Watch the whole playlist [Relational Databases for Beginners](https://www.youtube.com/watch?v=p5W4cVlVKqQ&list=PL3fg3zQpW0k4UO9eBDLdroADnB18ZAOgj). This should cover Relational modeling, database concepts and basics of SQL. Instead you could also use [Complete Intro to SQL & PostgreSQL](https://master.dev/courses/sql/).

Watch first two videos from the [CMU course on Database Systems](https://www.youtube.com/watch?v=7NPIENPr-zk&list=PLSE8ODhjZXjYMAgsGH-GtY5rJYZ6zjsd5). A lot of advanced concepts are covered in this course, and they will be very useful if you later do distributed systems.

Read chapters 4, 7 to 11 of [Head First SQL](https://www.amazon.com/Head-First-SQL-Brain-Learners/dp/0596526849/ref=pd_sbs_d_sccl_1_2/138-2989532-5408807). Note that this is older edition and is better. There are some good examples here, if you find joins hard to understand. Optional.

There are lots of decent examples in [SQL Cookbook](https://www.amazon.com/SQL-Cookbook-Query-Solutions-Techniques/dp/1492077445).

**Lab**:

Practice SQL using [PostgreSQL Exercises](https://pgexercises.com/gettingstarted.html)

Simpler alternative would be [sqlbolt](https://sqlbolt.com). Covers basics of SQL, subqueries, unions/intersections/exceptions, and more. Follow along the interactive tutorial.

[MySQL for Developers](https://planetscale.com/learn/courses/mysql-for-developers): Note that Section 4 contains examples for what you have learned in earlier sections. Optional.


## Unit 2: Testing Principles

- Learn essentials of unit testing with [Test Driven Development: By Example](https://www.amazon.com/Test-Driven-Development-Kent-Beck/dp/0321146530/). Part 1(chapters 1 to 17). As many as you can cover, these are really really short chapters, each around 4 pages.

- More specifically learn Arrange-Act-Assert pattern with [Unit Testing Principles, Practices, and Patterns](https://www.amazon.com/Unit-Testing-Principles-Practices-Patterns/dp/1617296279). Chapters 2 and 3. Also learn about [Given-When-Then](https://martinfowler.com/bliki/GivenWhenThen.html) pattern.

- Read chapters 1-6 from [Effective Software Testing: A developer's guide](https://www.amazon.com/dp/1633439933)
Learn basics of [Integration Testing](https://martinfowler.com/bliki/IntegrationTest.html)

- Learn the testing patterns: [The Practical Test Pyramid](https://martinfowler.com/articles/practical-test-pyramid.html) and [The Testing Trophy](https://kentcdodds.com/blog/write-tests)

Note that TDD might not be suitable for many projects. Also note that AAA might not be suitable for a lot of projects. Some might disagree the Testing Pyramid pattern. Learn both and use what's best for your project/team.

I personally pick Given-When-Then, Testing Trophy for most projects. I generally don't use test driven development. Still, I learnt most about testing from Kent Beck's book.

- [The Magic Tricks of Testing by Sandi Metz](https://www.youtube.com/watch?v=URSWYvyc42M)

- I would highly recommend reading first four chapters from [Refactoring](https://www.amazon.com/Refactoring-Improving-Existing-Addison-Wesley-Signature/dp/0134757599). Optional

**Lab**:

- Write unit tests for all Rust programs you have written till now using the principles above. Integrate this into git hooks and your CI/CD pipeline.


## Unit 3: Functional Programming in Rust

- In my opinion, Rust is the best functional programming language! Many disagree. First learn the most accurate description of [functional programming](https://www.amazon.com/Functional-Programming-Second-Michael-Pilquist/dp/1617299588) by reading chapter 1.

- You have already learned about value/identity/time. Read another, more [practical explanation](https://www.infoq.com/articles/Datomic-Information-Model/). Note that this equally good description of functional programming!

- Read chapter 13 and 19 from The Rust book.

- Read chapter 12 from The Rust book.
**Lab**:

- Use rustlings
- Implement a linked list with the list interface from 'Why functional programming matters'. Implement that interface for list. Use generics. Make sure the list is immutable. Write a few functions like insert, remove, reverse. Write tests for everything.

 Write basic integration tests. Try to separate functional code from imperative code. Write unit tests for functional code. Find some programs from [Command Line Rust](https://www.amazon.com/Command-Line-Rust-Project-Based-Primer-Writing/dp/1098109430) and do the same: split functional from imperative, write unit tests for pure core and integration tests for imperative shell.
