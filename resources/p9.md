## Unit 5: Deployment

Deployment depends on the cloud platform. Almost all cloud platforms provide excellent documentation and tutorials for deploying services. You already know Docker, Rust with Docker, continuous integration and deployment, observability, web APIs, Kubernetes, and GitHub Actions. Use this knowledge to deploy your services and APIs. Most of these cloud platforms also provide trials or credits, so getting started should be easy.

Use the [Docker Rust language-specific guide](https://docs.docker.com/guides/rust) to containerize your application. For deployment to Kubernetes on DigitalOcean, use [Build and Deploy Your First Image to Your First Cluster](https://docs.digitalocean.com/products/kubernetes/getting-started/deploy-image-to-cluster/).

Alternatively, use Microsoft Azure. The following tutorials should help:

- [Deploy a .NET microservice to Kubernetes](https://learn.microsoft.com/en-us/training/modules/dotnet-deploy-microservices-kubernetes/)
- [Implement observability in a .NET cloud-native application with OpenTelemetry](https://learn.microsoft.com/en-us/training/modules/implement-observability-cloud-native-app-with-opentelemetry/)
- [Deploy a cloud-native .NET microservice automatically with GitHub Actions and Azure Pipelines](https://learn.microsoft.com/en-us/training/modules/microservices-devops-aspnet-core/)

You could also follow this comprehensive learning path from Google Cloud:

- [Learning Path: Scalable applications - Overview](https://docs.cloud.google.com/kubernetes-engine/docs/learn/scalable-apps)

Understand the concepts, then use your AI agent and your prior knowledge to deploy your Rust microservice or web API project.


### Lab: Putting It All Together

With help from your mentor, pick one or two projects and implement them in a week or two using the knowledge you have gained over the past few months.

- Do not use event-driven architecture or event sourcing; they can take a lot of time. Do not use Temporal yet; you will use it in a later phase.
- Implement the projects with a few microservices using gRPC (Tonic) and/or REST (Axum), a PostgreSQL database (SQLx), and Docker, Podman, or Pod containers. Preferably, use Kubernetes.
- For small projects, CQRS is generally overkill. Evaluate whether it makes sense for the selected project.
- Create and follow guidelines for retries (with exponential backoff) and timeouts. Consider whether these can be generalized with configuration options.
- Pay extra attention to idempotency.
- Use the circuit breaker and rate limiting patterns.
- Use OpenTelemetry for observability with a backend like SigNoz or Grafana LGTM. Most cloud platforms provide their own backends too.
- When refactoring existing projects, consider the Strangler Fig pattern.
- Consider using domain-driven design.
- If you are using Kubernetes, consider the sidecar pattern.
- Create guidelines for secrets management, security, CI, and coding. Enforce them through linting tools and CI workflows where possible.
- Write integration tests and unit tests with good coverage. Design a CI pipeline and define it using GitHub Actions.
- Deploy the projects to your preferred cloud platform through CI workflows.
