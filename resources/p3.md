# Resources Part III


## Unit 1: Debugging

Watch [Debugging with the scientific method](https://www.youtube.com/watch?v=FihU5JxmnBg). Another good resource is chapter 6 of [Why Programs Fail](https://www.amazon.com/Why-Programs-Fail-Systematic-Debugging/dp/0123745152). Optionally, follow this by reading chapter 1 and 4.

A general approach to debugging: [Debugging](https://www.amazon.com/Debugging-Indispensable-Software-Hardware-Problems/dp/0814474578). It's a short and mostly conceptual book, skim through this in an hour or so.

You could use [Zed Debugger](https://www.youtube.com/watch?v=qgtClu2A8g4) or use [RustRover](https://www.jetbrains.com/rust/). For RustRover, use your AI agent to set it up correctly in NixOS or install it in distrobox(preferred). Resources in unit 4 should be helpful.

**Lab**: Start simple, solve simple programming problems(type/compile/logic errors) first. Use [rustlings](https://rustlings.rust-lang.org). This is a great companion for The Rust book. If you are stuck somewhere use [Learn Rust with Rustlings 5.2.1](https://www.youtube.com/watch?v=G3Vr-yswlaU)

*Note*: Use the same rustlings resource to practice all topics related to Rust. It should cover most important topics from the Rust book.

You will be provided with an internal project and a set of issues to get a better handle on debugging. Following resources might give you the mental framework to approach debugging, they in no way will be sufficient. Only a lot of experience and practice will help you become a better debugger.

## Unit 2: Rust Memory Model, Collections and Error Handling

Cover following sections from [The Rust Programming Language](https://master.dev/courses/rust/)

- Ownership
- Borrowing
- Lifetimes

These are difficult topics. A lot of this is already covered. Still you may have to come back to these again later to understand them fully.

Continue with the Rustlings.

Read *Common collections* and *Error handling* chapters from the Rust book.

**Lab**:

- Implement a singly linked list using the borrow checker ideas and database as a value(naive/basic) idea. Do not use any collections from standard library. Incorporate some of the knowledge you gained from error handling chapter.
- Rewrite your programs using collections and include robust error handling.
- Write a few more programs(larger) using  collections and error handling.

We will revisit error handling and data structures in later weeks.
