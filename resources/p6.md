After learning the above, implement the following project(or a project with similar complexity).

```markdown
Build a RESTful HTTP API for a small software development team to manage projects, programmers, and tasks.

The application allows programmers to organize themselves into teams, work on projects, assign tasks, and track progress. Each team has a designated lead who coordinates work and manages task assignments.

The primary objective is to learn how to **design, implement, and test practical HTTP APIs** using Rust, Axum, SQLx, and PostgreSQL.

Use xh and jq command line tools to manually test Web APIs.

### Requirements

#### 1. Programmers

A programmer represents a registered user of the application.

Each programmer has:

- Unique identifier
- Name
- Email address
- Account status (active or inactive)
- Creation timestamp

The API must support 
- Registering a programmer
- Retrieving programmer details
- Listing programmers
- Updating programmer information
- Deactivating a programmer
- Listing tasks assigned to a programmer


#### 2. Teams

Programmers can be organized into teams.

Each team has:

- Unique identifier
- Name
- Description
- Team lead
- Members
- Creation timestamp

The API must support:

- Creating and updating teams
- Listing teams and their members
- Adding programmers to teams
- Removing programmers from teams
- Assigning or changing a team lead
- Retrieving projects associated with a team

A programmer may belong to multiple teams.

Every active team must have exactly one designated lead, who must also be a member of that team. A programmer may lead multiple teams.

A team cannot be left without a lead. Removing its current lead requires assigning a replacement.

#### 3. Projects

A project represents a unit of work undertaken by a team.

Each project has:

- Unique identifier
- Name
- Description
- Owning team
- Status (`planned`, `active`, `completed`, `archived`)
- Creation timestamp

The API must support:

- Creating and updating projects
- Listing projects
- Retrieving a project
- Assigning a project to a team
- Changing project status
- Listing tasks belonging to a project

Each project belongs to exactly one team. A team may own multiple projects.

#### 4. Tasks

Tasks represent individual pieces of work within a project.

Each task has:

- Unique identifier
- Project identifier
- Title
- Description
- Status (`todo`, `in_progress`, `blocked`, `done`)
- Priority (`low`, `medium`, `high`)
- Assigned programmer (optional)
- Due date (optional)
- Creation and update timestamps
- Version number for concurrency control

The API must support:

- Creating, retrieving, updating, and deleting tasks
- Assigning and reassigning tasks
- Changing task status and priority
- Listing tasks belonging to a project
- Listing tasks assigned to a programmer
- Filtering, sorting, and paginating task collections

A task may only be assigned to a programmer who belongs to the project's owning team.

An unassigned task is allowed.

Do not attempt authentication/authorization at this point, takes a week to correctly implement.
```
